No keys or secrets appear in this report.

1. Executive summary

The Federal Funds Matchmaker is meant to help NC agency grant coordinators find federal funding opportunities that fit their agency and act before the deadline, with a human making every final call. Today a small proof runs on Azure Container Apps at a public URL with no login, showing 6,523 public opportunities in a table, plus the qualifier tool as a static page. There is no matching, scoring or AI running yet. The plan (Kent's product decisions) is to host the qualifier-style JS tool, reading a payload file from Blob storage, with Azure OpenAI writing embeddings and reasons that a script checks against their sources. The biggest security gaps today are the missing login and a keys file committed to the private repo, which must be fixed before any public or State handoff. Whether Azure OpenAI keeps prompts out of training is [uncertain] and stays that way until the Azure documentation is read.

8. Recommended next steps

  1. Before any public or State handoff: rotate the two API keys, remove api_keys.env from the repo and its history, and hold secrets outside the repo.
  2. Decide whether Azure OpenAI is ours to create; read the Azure data-handling documentation before anyone claims prompts are not used for training; settle the sponsor privacy question (the "local model" answer).
  3. Before the demo, set min replicas to 1 so the first page load is not 38 seconds; set it back afterward.
  4. When the Blob flow is built: managed identity with a least-privilege role (ask first), upload payload only after the team lead agrees.
  5. For a pilot: sign-in (Entra ID), rate limit, an as-of date on screen, an audit trail of decisions, and manual monitoring kept as the baseline.

17. Glossary

  • C4 container view: a picture of the main deployable parts of a system.
  • STRIDE: six threat types: spoofing, tampering, repudiation, information disclosure, denial of service, elevation of privilege.
  • Trust boundary: a line where data passes between zones of different trust.
  • Managed identity: an Azure-managed account for a service, so no password is stored.
  • Zero Trust: verify every request, give least privilege, assume breach.
  • Prompt injection: text in the input that tries to steer the model.
  • Power/interest grid, onion model, RACI: ways to place stakeholders by influence and concern, by closeness to the product, and by who is Responsible, Accountable, Consulted or Informed.
