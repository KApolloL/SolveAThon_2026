1. Executive summary

Federal Funds Matchmaker helps North Carolina state agencies find federal grant opportunities that fit their strategic priorities. Each night an Azure Function App pulls opportunities from Grants.gov and SAM.gov and turns agency strategic plans into structured profiles with Azure OpenAI. It then scores each opportunity–agency pair with an explainable fit score. Agency grant managers review a ranked, summarized shortlist in a web app and make the final apply/skip decision; the AI only recommends.

The security posture is reasonable for a prototype: all source data is public, users sign in with Entra ID, and services use Managed Identity. The main risks are prompt injection through ingested documents (T5), incorrect AI matches (T8), and API keys stored outside Key Vault (T6). All three have concrete mitigations below.

8. Assumptions & open questions

  • ASSUMED Cosmos DB is the database (deck says "database" only). Confirm the service.
  • ASSUMED Users sign in with Entra ID through App Service authentication. Is sign-in enabled?
  • ASSUMED Application Insights is enabled on both apps.
  • ASSUMED All ingested data is public. Internal agency notes are not stored.
  • Open question: How are scoring weights governed, and who may change them?
  • Open question: Is there a retention policy for raw payloads in Blob Storage?

9. Recommended next steps

  1. Move the SAM.gov key into Key Vault, rotate it, and enable secret scanning (T6).
  2. Add prompt-injection defences and output schema validation (T5).
  3. Build a 30-item labelled evaluation set to measure false positives and false negatives (T8).
  4. Disable key-based auth on Cosmos DB and Storage; use data-plane RBAC (T7).
  5. Capture infrastructure in Bicep and add Azure AI Search for grounded citations.

10. Glossary

C4 model
A way to draw software architecture at four zoom levels: Context, Container, Component, Code.
Container (C4)
A separately deployable or runnable unit, such as a web app, function app, or database. It is not the same as a Docker container.
Data-flow diagram (DFD)
A diagram of how data moves between entities, processes and stores. It is the basis of most threat models.
Trust boundary
A line where the level of trust changes, such as between the internet and your cloud. Threats concentrate where data crosses it.
STRIDE
Microsoft's threat categories: Spoofing, Tampering, Repudiation, Information disclosure, Denial of service, Elevation of privilege.
OWASP Top 10 for LLM
The ten most critical security risks for applications that use large language models.
Managed Identity
An Azure-managed identity that lets a service authenticate to another service without storing secrets.
Zero Trust
A security model: verify explicitly, use least privilege, assume breach.
Well-Architected Framework
Microsoft's five pillars for evaluating cloud workloads.
NIST CSF 2.0
US cybersecurity framework: Govern, Identify, Protect, Detect, Respond, Recover.
